## Risks & open questions

1. **Room ID type.** `docs/conventions.md` currently assumes `Guid` for both Room and Booking
   IDs. Rooms are fixed/pre-seeded with no discovery endpoint (out of scope), so callers need a
   stable, human-referenceable ID. **Recommendation:** Room.Id is a stable string slug
   (`"alpha"`/`"beta"`/`"gamma"`); Booking.Id stays a server-generated `Guid`. Will correct
   `docs/conventions.md` in step 6 rather than silently diverge from it.
2. **BR-5 (UTC) enforcement.** A non-UTC offset on the wire (e.g. `+02:00`) needs a treatment.
   **Recommendation:** treat it as a 4th `Invalid` violation (`NotUtc`) inside `Booking.TryCreate`
   — consistent with "expected violations are outcomes, not exceptions."
3. **New test-only dependencies:** `NetArchTest.Rules` (Application.Tests) and
   `Microsoft.AspNetCore.Mvc.Testing` (Api.Tests). **Recommendation:** approve — both are
   standard, actively maintained, MIT-licensed, and never ship in a production assembly. Neither
   is a DB/ORM/auth package, so this doesn't touch the forbidden-dependency rule.
4. **In-memory repository concurrency.** No locking/thread-safety is added in v1.
   **Recommendation:** accept as a known limitation of the "in-memory, single-office prototype"
   scope already documented in `docs/architecture.md` — not a defect to fix here.
5. **Seed data specifics.** Exact 3 rooms are arbitrary but must be concrete for deterministic
   tests. **Recommendation:** accept `alpha`/`beta`/`gamma` as placeholder seed data; real room
   provisioning is explicitly a future feature.
